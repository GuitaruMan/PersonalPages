이 문서는 슬라이드를 화면에서 어떻게 짜는가만 다룬다. 무엇을 쓸 것인가(내용 선정·문체·인용 검증)는 작업지침 쪽에 있다. 아래 규칙은 모두 실제로 문제가 생겨 고친 것들이고, 고친 이유를 함께 적어 둔다.

1무대와 여백

슬라이드 한 장은 .stage 하나다. 16:9를 유지하고, 안쪽 치수는 모두 cqw(컨테이너 너비의 1%) 기준으로 잡는다. px는 쓰지 않는다.

.stage {
  container-type: inline-size;
  --stage-w: min(100%, 1180px, (100vh - 8.5rem) * 16 / 9);
  width: var(--stage-w);
  aspect-ratio: 16 / 9;
  padding: calc(var(--stage-w) * 0.042) calc(var(--stage-w) * 0.05);
}
body:fullscreen .stage {
  --stage-w: min(100vw, calc(100vh * 16 / 9));
  width: var(--stage-w);
  height: min(100vh, calc(100vw * 9 / 16));
}
왜 이렇게 쓰는가

padding: 4.2% 5.4%처럼 %로 두면 안 된다. padding의 %는 .stage가 아니라 body 너비를 기준으로 계산된다. 창이 넓을수록 여백만 커지고 cqw 기준 본문은 작아진다. 1920 창모드에서 1cqw가 11.78px이어야 하는데 9.94px이 되던 문제였다. --stage-w를 정의해 padding을 무대 너비로 묶으면 어떤 해상도에서도 안쪽이 100cqw × 52.64cqw로 고정된다. 전체화면 규칙에도 --stage-w를 다시 정의해야 한다.

max-width: 1180px만 주는 것도 안 된다. 화면이 낮을 때 body의 세로 중앙 정렬 때문에 슬라이드 위아래가 동시에 잘리고 스크롤로도 볼 수 없다. 위 min() 식이 그것까지 막는다.

2글자 크기 — 슬라이드마다 다르게

슬라이드마다 내용의 양이 다르므로 글자 크기도 달라야 한다. 덱 전체에 한 크기를 쓰면 내용이 적은 장은 휑하고 많은 장은 넘친다. --fs 배율을 두고 슬라이드마다 지정한다.

:root { --fs: 1; }

/* 본문은 배율을 탄다 */
.emotion li { font-size: clamp(0.82rem, calc(1.82cqw * var(--fs)), calc(2.18rem * var(--fs))); }

/* 제목·표지·쪽번호는 배율에서 뺀다 */
h2.slide-title { font-size: clamp(1.45rem, 3.85cqw, 4.62rem); }
<section class="slide" style="--fs:1.32;">
제목을 배율에서 빼는 이유

제목이 함께 커지면 본문이 쓸 자리를 먹는다. 배율 탐색이 제목까지 키우려 들어 정작 본문은 덜 커진다. 제목은 덱 전체에서 3.85cqw로 고정해 두면 자료끼리도 통일된다.

배율은 눈대중이 아니라 실측한다

슬라이드마다 이분 탐색으로 넘치지 않는 최대값을 찾는다. 안전계수 0.96을 곱하고 상한은 1.45로 둔다. 상한이 없으면 내용이 적은 장의 글자가 우스꽝스럽게 커진다.

let lo = 0.8, hi = 1.46;
for (let k = 0; k < 18; k++) {
  const mid = (lo + hi) / 2;
  if (fits(mid)) lo = mid; else hi = mid;
}
const scale = Math.min(1.45, +(lo * 0.96).toFixed(2));

fits()가 확인할 네 가지는 8장의 검증 항목과 같다. 측정은 1920×1080과 1366×768 두 해상도에서 각각 재고 작은 쪽을 쓴다.

측정값이 안전계수 때문에 1.0 아래로 내려가면 1.0으로 되돌린다. 그건 “지금 크기가 이미 딱 맞다”는 뜻이지 줄이라는 뜻이 아니다.

3여백은 글자를 따라간다

글자만 키우고 여백을 cqw·rem으로 두면, 커진 글자끼리 서로 붙어 오히려 읽기 나빠진다. 요소 사이 여백은 em으로 잡는다. em은 그 요소의 글자 크기를 기준으로 하므로 배율을 자동으로 따라간다.

.emotion li + li  { margin-top: 0.55em; }
.c3 p + p         { margin-top: 0.72em; }
.word-note        { margin-top: 0.9em; padding-top: 0.8em; }
.num-list li      { margin-bottom: 0.75em; }
.info-table th,
.info-table td    { padding: 0.62em 0.5em; }

바깥 치수(무대 여백, 칸 사이 간격)는 cqw로 두어 화면 비율을 따르게 하고, 글자 사이 여백만 em으로 둔다. 이 둘을 섞지 않는다.

자리가 빠듯한 슬라이드는 예외로 둔다

여백을 넉넉히 주면, 원래도 꽉 차 있던 슬라이드는 오히려 글자를 줄여야 들어간다. 그런 장에는 .tight를 붙여 여백만 줄이고 글자 크기는 지킨다. 머리말을 가르는 선은 그대로 둔다.

.slide.tight .emotion li + li { margin-top: 0.34em; }
.slide.tight .word-note       { margin-top: 0.6em; padding-top: 0.5em; }
.slide.tight .info-table th,
.slide.tight .info-table td   { padding: 0.45em 0.45em; }

그러고도 배율이 1.0에 못 미치면 그때는 내용을 덜어낸다. 대개 오른쪽 시어 풀이와 아래 해설이 같은 말을 두 번 하고 있다.

4내용 사이 경계

상자의 머리말과 본문을 선으로 가른다

제목과 내용이 여백만으로 구분되면, 글자가 커질수록 한 덩어리로 보인다.

.def-box .dt,
.emotion .etag {
  margin-bottom: 0.62em;
  padding-bottom: 0.42em;
  border-bottom: 1px solid var(--rule);
}

작품의 말과 해설을 가른다

카드 안에서 원문을 옮겨 적은 줄과 그에 대한 해설이 같은 모양이면 어느 쪽이 작품의 말인지 알 수 없다. 인용 줄에 .cite를 준다.

.c3 p.cite {
  font-family: "Gowun Batang", "Noto Serif KR", serif;   /* 본문 글꼴로 */
  background: rgba(0,0,0,0.04);                          /* 옅은 바탕 */
  border-left: 0.28em solid var(--rule);                 /* 왼쪽 선 */
  padding: 0.5em 0.72em;
  margin-bottom: 0.8em;
  color: var(--ink);
}
.c3 p.cite + p { margin-top: 0; }
색이 아니라 바탕과 선으로 가른다

인용을 강조색으로 칠하면, 제목·라벨도 같은 색이라 화면에 강조색이 넘쳐 오히려 구분이 흐려진다. 바탕·선·글꼴로 가르면 색을 쓰지 않고도 층이 생긴다.

연별 정밀 분석 슬라이드는 이미 .cols로 왼쪽 원문 · 오른쪽 시어 풀이가 갈려 있고 각 칸에 .col-head가 붙는다. 이 구조를 흩뜨리지 않는다.

5쪽번호

쪽번호는 본문칸 밖, 무대 여백에 둔다.

.page-num { position: absolute; right: 0; bottom: -3.1cqw; }
.cover .page-num { display: none; }
왜 밖으로 내보내는가

본문칸 안쪽 아래에 두면 본문이 아래까지 찼을 때 글자를 덮는다. 그걸 피하려고 상자마다 margin-bottom을 억지로 두게 되고, 그만큼 본문이 쓸 자리가 준다. 쪽번호를 무대 여백으로 내리면 본문이 칸을 온전히 쓰고 회피용 여백도 필요 없어진다.

6색 — 구조와 강조를 가른다

덱마다 작품 분위기에 맞는 강조색을 하나 정하고, CSS 변수만 바꾼다.

작품강조색바탕
가시리단청 붉은색 #a8322a한지
묏버들버들 초록 #3f7048한지
개여울물빛 #2f6b8f한지
춘향전자주 #8a2b52한지
폭포물빛 청록 #0d6a82찬 색지 #eef4f7

강조색은 화면의 구조에 쓴다. 슬라이드 제목, 칸 머리말, 항목 번호, 화살표, 상자의 왼쪽 선. 여기까지다.

본문 강조는 색을 바꾸지 않는다

원문에서 짚는 시어를 강조색으로 칠했더니, 바탕도 청록 계열이고 제목도 같은 색이라 강조한 티가 나지 않았다. 그렇다고 보색(호박빛)으로 바꾸니 자료 분위기에서 겉돌았다. 결론은 같은 강조색을 쓰되 획을 조금 두껍게 하는 것이다.

/* Gowun Batang은 400·700 두 굵기뿐이라 font-weight로는 더 굵어지지 않는다.
   획 두께를 직접 더한다. 글자 폭은 그대로여서 줄바꿈에 영향이 없다. */
.verse .hl {
  color: var(--fall); font-weight: 700;
  -webkit-text-stroke: 0.022em currentColor;
}

본문 속 일반 강조는 <strong>으로 굵게만 한다. 색을 더하지 않는다.

바탕과 모티프

무대 바탕에 작품 모티프를 opacity 0.13~0.16으로 옅게 깐다. 제목 아래에서 시작하도록 top을 잡아야 제목 밑줄과 겹쳐 보이지 않는다. SVG data URI는 반드시 한 줄로 쓴다. 줄바꿈으로 이어 쓰면 공백이 섞여 깨진다.

7단계 공개 — 확인 문제

확인 문제는 문항과 정답을 한 화면에 미리 다 보여 주지 않는다. 학생이 답한 뒤 바로 확인시켜야 하므로, 스페이스·클릭·좌우 방향키로 문항 → 정답 → 다음 문항 → 정답 순서로 하나씩 드러낸다.

.reveal { opacity: 0; transition: opacity .25s ease; }
.reveal.shown { opacity: 1; }
display가 아니라 opacity로 숨기는 이유

opacity는 자리를 미리 차지한 채 숨는다. 답이 나타날 때 아래 내용이 밀리거나 화면이 튀지 않는다. 수업 중에는 이 안정감이 중요하다.

function revealsOf(i) { return Array.from(slides[i].querySelectorAll('.reveal')); }

function next() {
  const hidden = revealsOf(idx).find(el => !el.classList.contains('shown'));
  if (hidden) { hidden.classList.add('shown'); updateButtons(); return; }
  if (idx < slides.length - 1) show(idx + 1);
}

function prev() {
  const shown = revealsOf(idx).filter(el => el.classList.contains('shown'));
  if (shown.length) { shown[shown.length - 1].classList.remove('shown'); updateButtons(); return; }
  if (idx > 0) show(idx - 1, true);   // 뒤로 갈 때는 그 장의 단계를 모두 펼친 상태로
}
  • 스페이스 · ← → · 클릭 — 한 단계씩
  • ↑ ↓ — 단계를 건너뛰고 장 단위로 이동 (수업 중 급히 넘길 때)
  • 한 장에 두 문항까지. 자리가 남으므로 문제 글자는 원문만큼 크게 잡는다

8검증

python -m http.server로 띄우고 확인한다. file://은 열리지 않는다. Playwright는 토큰을 많이 쓰므로 browser_evaluate 한 번으로 전 덱·전 슬라이드를 한꺼번에 검사하고 문제 목록만 받는다. 스크린샷은 정말 눈으로 봐야 할 때 한두 장만.

덱을 iframe에 srcdoc으로 띄우고 1920×1080 / 1600×900 / 1366×768 / 1280×720을 순회한다. 단계 공개가 있는 덱은 검사 전에 .reveal을 모두 펼친다.

항목무엇을 재는가왜 필요한가
잘림.body-area의 scrollHeight > clientHeight 본문칸 안에서 내용이 잘림
무대 밖슬라이드의 모든 요소가 .stage 밖으로 나가는지 아래위가 화면을 벗어남
겹침.cols·.cards* 안 요소의 아래쪽이 뒤따르는 .emotion 위를 넘는지 잘림 검사로는 못 잡는다. 칸 안 내용이 넘쳐 아래 상자에 가려도 .body-area의 높이는 그대로다
쪽번호Range.selectNodeContents로 잰 실제 글자 사각형이 .page-num과 겹치는지 요소 사각형으로 재면 전폭 블록이 모두 오탐이 된다

통과 기준은 네 항목 모두 0이다.

겹침 검사를 빠뜨리지 말 것

.cols > div는 그리드 항목이라 칸 높이에 맞춰 늘어난다. 그 안에서 내용이 넘쳐도 바깥 .body-area는 아무 변화가 없어서, 잘림 검사만 돌리면 “이상 없음”이 나온다. 실제로는 시어 풀이 마지막 항목이 해설 상자에 36px 가려져 있었다.

9작업 순서와 체크리스트

  1. 기준 파일을 복제한다. 골격을 새로 짜지 않는다
    • 고전·현대 문학: work/수업/폭포_1학년_1차시.html
    • 수능 독서: work/수업/수능국어_1회_1-3번.html
  2. 색 변수와 바탕 모티프만 작품에 맞게 바꾼다
  3. 내용을 채운다. 배율은 아직 넣지 않는다(모두 --fs 없이 1.0)
  4. 검증 스크립트로 넘침이 없는지 먼저 확인한다
  5. 배율을 실측해 슬라이드마다 style="--fs:…"로 적는다
  6. 1.0 미만이 나온 장에 .tight를 붙이고 다시 잰다
  7. 그래도 1.0 미만이면 그 장의 내용을 덜어낸다
  8. 네 해상도로 최종 검증 → 학년 목록에 카드 추가 → main에 푸시
  • --stage-w가 .stage와 전체화면 규칙 양쪽에 정의되어 있는가
  • 본문 font-size가 모두 --fs 배율을 타는가 (제목·표지·쪽번호는 제외)
  • 요소 사이 여백이 em인가
  • 상자 머리말 아래에 구분선이 있는가
  • 원문 인용 줄과 해설이 갈려 보이는가
  • 쪽번호가 본문칸 밖에 있는가
  • 강조색이 화면 구조에만 쓰였는가 (본문 강조는 굵기로)
  • 확인 문제가 단계 공개로 되어 있는가 (한 장에 두 문항까지)
  • .page-num과 하단 #counter의 총 장수가 실제 슬라이드 수와 맞는가
  • 네 해상도에서 잘림·무대 밖·겹침·쪽번호가 모두 0인가
이 문서는 work/수업/의 8종(가시리·묏버들·개여울·춘향전 1~3차시·폭포 1~2차시)에 실제로 적용된 규칙을 정리한 것이다. 내용 선정·문체·원문 검증·게시 절차는 수업자료 작업지침에 있다.
