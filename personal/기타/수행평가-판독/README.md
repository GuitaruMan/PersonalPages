# 수행평가 답안 판독 — 도구와 절차

학생 답안(원고지 스캔 PDF)을 Claude Code가 판독할 때 쓰는 도구와 지켜야 할 규칙이다.
2026-09-23에 4반을 두 번 판독하면서(첫 판독은 전량 폐기) 정리했다.

**이 문서만 읽고 시작하지 말 것.**
같은 폴더 상위의 [`수행평가1-채점기준.md`](../수행평가1-채점기준.md) **§4-A 전체**를 먼저 읽는다.
거기에 칸 단위 판독 원칙, 실제 저지른 오류 목록, 효과가 있었던 방법이 있다.
이 README는 그 요약과 도구 사용법이고, **판단이 갈리면 §4-A가 기준이다.**

## 0. 다른 컴퓨터에서 시작하기

```sh
git clone https://github.com/GuitaruMan/PersonalPages.git
cd PersonalPages/personal/기타/수행평가-판독
pip install pymupdf pillow numpy
```

**`grid.json`을 만든다.** 이 폴더에 없으면 `grid4.py`가 양식을 찍어 준다.

```sh
python grid4.py block 1 1 7     # grid.json 이 없으면 만드는 법을 알려 준다
```

```json
{
  "pdf": "답안 PDF 경로",
  "rows": 35,
  "cols": 30,
  "odd":  {"y0": 264, "y1": 1664, "x0": 104, "x1": 1166},
  "even": {"y0": 87,  "y1": 1487, "x0": 104, "x1": 1166},
  "norm_w": 1214,
  "norm_h": 1720
}
```

`odd`/`even`은 **폭 1214·높이 1720으로 정규화한 원고지 격자의 픽셀 좌표**다.
홀수쪽은 위에 이름칸이 있어 `y0`가 더 아래에서 시작한다.

**좌표는 반마다 다르다. 반드시 실측한다.**
블록을 한 장 뽑아 맨 윗줄이 1행 맨 위에, 맨 아랫줄이 마지막 행 맨 아래에
딱 맞는지 눈으로 확인한다. 어긋나면 `y0`/`y1`을 조정한다.
확정한 값은 기록해 두고 다음부터 그 기록을 읽어 쓴다(기억에 의존하지 않는다).

## 1. 도구

| 파일 | 용도 |
|---|---|
| `grid4.py` | 답안 블록 렌더링. **칸 번호 눈금이 위에 찍힌다** — 이게 핵심 |
| `v30.py` | 칸 검사. 30칸 초과 · `⟨ ⟩` 짝 불일치를 잡는다 |
| `trim.py` | 30칸 초과 행을 원본 관행(부호는 앞 칸에 붙음)에 맞춰 줄인다 |

```sh
python grid4.py block <쪽> <시작행> <끝행> [dpi]      # 기본 150dpi → b{쪽}_{시작}-{끝}.png
python grid4.py cell  <쪽> <행> <시작칸> <끝칸> [dpi]  # 애매한 글자 확대 → c.png
python grid4.py row   <쪽> <행> [dpi]                 # 한 행 전체
python v30.py --all            # 저장한 판독문 전부 검사
python v30.py s5_03.json       # 한 명만
python trim.py s5_03.json      # 초과 행 자동 보정
```

## 2. 판독 절차 (학생 1명)

1. 이름칸(`{홀수쪽}h`)으로 반·번호·이름 확정 → 명단과 대조
   학생이 반·번호를 틀리게 쓴 경우가 있다 (4반 3번은 "3반 4번"으로 적었다).
   판독 중 메모한 이름을 믿지 말고 이름칸 이미지를 다시 본다
   (4반 12번을 "김세민"으로 메모했으나 실제는 "유상민"이었다).
2. 1쪽을 **7행 블록 5개**로 읽는다 — `block <쪽> 1 7`, `8 14`, `15 21`, `22 28`, `29 35`
3. 애매한 글자만 `cell`로 확대 (700~1600dpi)
4. **2쪽 판단** — 아래 규칙
5. `s{반}_{번호:02d}.json` 저장
6. **`v30.py`로 검사** → 걸린 행을 다시 본다
7. 통과한 뒤에 다음 학생

한 명 끝낼 때마다 저장한다. 세션이 끊겨도 이어서 할 수 있다.

### 2쪽(뒷장) 판단 규칙 — 교사 확정

- 학생마다 **2쪽씩** 스캔되어 있다. 빈 쪽도 다 스캔했다.
  교사가 눈으로 확인하려고 일부러 그렇게 한 것이니, 빈 쪽이 있다고 이상한 게 아니다.
- **2쪽 맨 위 2줄이 비어 있으면 그 쪽은 백지**로 본다. 그 아래는 읽지 않아도 된다.
- **다만 예외가 있다.** 2줄 이상 띄운 뒤 아래쪽에 이어 쓰거나,
  원고지 밖 여백에 쓴 학생이 있다 (3반 4번·12번, 4반 2번).
  그래서 **2줄 규칙에 걸려도 쪽 전체를 한 번은 훑는다.**
  `block <2쪽> 8 14`, `15 21` 정도만 더 보면 충분하다.
- 1쪽이 백지인 경우는 거의 없다.
- 번호·이름 머리가 없는 쪽은 **앞 학생의 뒷장**이다.
- 원고지 밖 여백에 쓴 줄도 답안에 포함해 판독하고 분량에도 넣는다.
  그 줄은 칸 격자가 없으므로 30칸 검사에서 예외로 두고, `note`에 적는다.

## 3. 판독문 JSON 형식

```json
{
 "n": 3,
 "name": "김대현",
 "work": "목련 후기",
 "pages": [5, 6],
 "tx": ["1행", "2행", "..."],
 "chars": 0,
 "note": "편집기호·특이사항. 본문 줄에는 주석을 넣지 않는다"
}
```

- `pages`는 **PDF 쪽 번호** (1쪽, 2쪽)
- `tx`는 원고지 행 순서대로. 1쪽 35행 다음에 2쪽이 이어진다
- 띄어쓰기는 **원본 그대로**. 고치지 않는다 (채점 항목이다)
- 불확실한 곳은 `⟨글자⟩`. **한 줄 안에서 열고 닫는다**
  (줄을 넘어가는 단어는 `…⟨신⟩` / `⟨화⟩와…` 처럼 각 줄에서 따로 닫는다)
- `[여백]`, `[순서바꿈]`, `[취소선]` 같은 표시는 **`note`에만** 적는다.
  본문 줄에 넣으면 칸 계산이 깨진다

## 4. 꼭 지킬 것 (실제 사고에서 나온 것들)

1. **칸으로 읽는다.**
   "이 문장이 무슨 뜻인가"가 아니라 **"1번 칸에 무엇, 2번 칸에 무엇"** 순으로 확정한다.
   `grid4.py`가 칸 번호를 찍어 주는 이유가 이것이다.
   → 4칸짜리 "몰입하게"를 3칸 "슬프게"로 읽은 적이 있다. 격자는 눈에 보인다.
   → 첫 판독 때 910행 중 444행이 30칸을 넘었는데 **한 번도 세어보지 않고** "완료"라고 보고했다.

2. **띄어쓰기를 자연스럽게 고치지 않는다.**
   원본이 `봄이왔는데`면 그대로 쓴다. 맞춤법 오류도 그대로. 그게 감점 대상이다.

3. **맥락으로 짐작해 채우지 않는다.**
   작품명·인명·문법을 아는 지식으로 끌어다 맞춘 것이 전부 오류였다
   (「목련 후기」를 「묏버들」로, '나는'을 '나ᄂᆞᆫ'으로).
   획 하나 차이면 맥락으로 읽되 **반드시 `⟨ ⟩` 표시**를 한다.
   전혀 안 보이면 `▯`로 칸을 채워 **칸 수는 지킨다.**

4. **원본 PDF에서만 렌더링한다.**
   내가 만든 축소 이미지로 판단하지 않는다 (해→태, 있→오로 잘못 읽은 적이 있다).

5. **표시를 남발하지 않는다.**
   거의 모든 어절에 `⟨ ⟩`를 달면 교사가 쓸 수 없다.
   그 정도로 안 읽히면 판독 방법을 바꾸거나 교사에게 직접 보라고 알린다.

6. **서브에이전트에 맡기지 않는다.**
   직접 읽는 편이 더 빠르고 정확했다. 에이전트 로그에 스스로
   "unreliable transcriptions"라고 적혀 있었다.

7. **토큰을 아낀다.**
   학생당 블록 5~8장이면 충분하다. 글자 하나당 이미지를 만들면 감당이 안 된다.

### 연필 흐림에서 잦은 오독

획을 놓쳐 획이 적은 글자로 읽는다: 간→란, 년→련, 제→체, 모→또, 두→주

## 5. 서버에 올리기

판독 결과는 Cloudflare Worker(`suhaeng1`)의 `src/data.js`에 넣어 배포한다.

```sh
# 1) 서버의 현재 DATA 를 브라우저로 받는다 (Cloudflare Access 때문에 curl 불가)
#    페이지에서: JSON.stringify(DATA) → Blob → 다운로드
# 2) 받은 파일을 기준으로 해당 반만 추가/교체
# 3) bash deploy.sh
```

**로컬 `data.js`가 최신이라고 가정하지 말 것.**
2026-09-23에 그렇게 해서 다른 반 판독문과 교사가 수정한 화면 코드를 전부 날렸다.
복구는 `npx wrangler rollback <version-id>`로 했다.
(`wrangler deployments list`의 시각은 **UTC**다. 한국시간은 +9시간)

`deploy.sh`는 `tools/guard.py`를 거친다. 이전 배포보다 **반이 사라지거나
학생 수가 줄면 배포를 막는다.** 의도한 삭제라면 `tools/deployed_classes.json`을
지우고 다시 실행한다.

### 불확실 표시가 화면에서 보이는 방식

판독문의 `⟨글자⟩`는 교사 화면에서
- 그 줄이 빨갛게 표시되고
- 오른쪽에 확인할 글자만 칩으로 따로 나오고
- **입력칸에는 `⟨ ⟩`가 보이지 않는다** (교사가 괄호를 지울 필요 없음)
- 맞으면 칩을 눌러 확정, 틀리면 입력칸에서 글자만 고치면 된다
