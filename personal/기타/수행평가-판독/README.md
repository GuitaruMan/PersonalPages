# 수행평가 답안 판독 지침

학생 답안(원고지 스캔 PDF)을 **판독문(원고지 줄 단위 텍스트)으로 옮기고 서버에 올리는 일**만 다룬다.
Claude Code가 판독할 때 읽는다. 채점·피드백은 [`수행평가1-채점기준.md`](../수행평가1-채점기준.md)에 있다.

**판독이 채점보다 먼저다.** 판독이 틀리면 그 뒤 채점·피드백이 전부 무의미하다.
칸 검사(§2-2)를 통과하지 못한 판독문으로는 채점하지 않는다.
2026-09-23에 4반 22명을 판독했다가 칸이 맞지 않아 전량 폐기했다. 이 문서의 규칙은 그때와 그 뒤의 실제 오류에서 나왔다.

- 최종 수정: 2026-09-28

## 0. 다른 컴퓨터에서 시작하기

```sh
git clone https://github.com/GuitaruMan/PersonalPages.git
cd PersonalPages/personal/기타/수행평가-판독
pip install pymupdf pillow numpy
```

**`grid.json`을 만든다.** 이 폴더에 없으면 `grid4.py`가 양식을 찍어 준다.

```sh
python grid4.py block 1 1 7     # grid.json 이 없으면 만드는 법을 알려 준다
```

```json
{
  "pdf": "답안 PDF 경로",
  "rows": 35,
  "cols": 30,
  "odd":  {"y0": 264, "y1": 1664, "x0": 104, "x1": 1166},
  "even": {"y0": 87,  "y1": 1487, "x0": 104, "x1": 1166},
  "norm_w": 1214,
  "norm_h": 1720
}
```

`odd`/`even`은 **폭 1214·높이 1720으로 정규화한 원고지 격자의 픽셀 좌표**다.
홀수쪽은 위에 이름칸이 있어 `y0`가 더 아래에서 시작한다.

**좌표는 반마다 다르다. 반드시 실측한다.**
블록을 한 장 뽑아 맨 윗줄이 1행 맨 위에, 맨 아랫줄이 마지막 행 맨 아래에
딱 맞는지 눈으로 확인한다. 어긋나면 `y0`/`y1`을 조정한다.
확정한 값은 기록해 두고 다음부터 그 기록을 읽어 쓴다(기억에 의존하지 않는다).

## 1. 도구

| 파일 | 용도 |
|---|---|
| `grid4.py` | 답안 블록 렌더링. **칸 번호 눈금이 위에 찍힌다** — 이게 핵심 |
| `v30.py` | 칸 검사. 30칸 초과 · `⟨ ⟩` 짝 불일치를 잡는다 |
| `trim.py` | 30칸 초과 행을 원본 관행(부호는 앞 칸에 붙음)에 맞춰 줄인다 |
| `halves.py` | 한 행을 1~15칸 / 16~30칸으로 나눠 크게 보여 준다. `GAMMA=2.5` 로 흐린 연필 보정 → `m.png` |
| `cellrow.py` | `칸번호:글자` 로 적은 것을 30칸 행으로 만든다(칸 수가 틀릴 수 없음) |

```sh
python grid4.py block <쪽> <시작행> <끝행> [dpi]      # 기본 150dpi → b{쪽}_{시작}-{끝}.png
python grid4.py cell  <쪽> <행> <시작칸> <끝칸> [dpi]  # 애매한 글자 확대 → c.png
python grid4.py row   <쪽> <행> [dpi]                 # 한 행 전체
python v30.py --all            # 저장한 판독문 전부 검사
python v30.py s5_03.json       # 한 명만
python trim.py s5_03.json      # 초과 행 자동 보정
GAMMA=2.5 python halves.py 3 1 2 3 4 5   # 3쪽 1~5행을 반쪽씩 크게
```

## 2. 판독 원칙

### 2-1. 원고지는 "문장"이 아니라 "칸"으로 읽는다

**이것이 가장 중요하다.** 원고지는 한 글자 = 한 칸이고 **빈칸도 글자와 똑같이 의미가 있다.**
띄어쓰기 오류가 D 영역 감점 요인이므로, 칸 배치가 틀리면 채점 자체가 불가능하다.

- 한 줄은 **정확히 30칸**이다. 판독한 줄의 글자 수(빈칸 포함)는 **반드시 30이어야 한다.**
  마지막 줄만 30칸 미만일 수 있다.
- 읽을 때 "이 문장은 무슨 뜻인가"가 아니라 **"1번 칸에 무엇, 2번 칸에 무엇"** 순으로 확정한다.
  `grid4.py`가 블록 위에 칸 번호를 찍어 주는 이유가 이것이다.
- 학생의 띄어쓰기·맞춤법 오류를 **고쳐 적지 않는다.** 원본 그대로 옮긴다. 그 오류가 감점 대상이다.
- 문단 시작의 들여쓰기 한 칸도 빈칸 하나로 센다.

**실제 오류 사례 (2026-09-23, 4반 3번 2쪽 19행)**
- 원본: `욱 · 몰 입 하 게 · 되 었 다` (11칸)
- 잘못 판독: `욱 슬프게 되었다` (10칸) — 4칸짜리 "몰입하게"를 3칸짜리 "슬프게"로 읽었다
- 글자 모양이 애매했던 게 아니라 **칸을 세지 않은 것**이 원인이다. 격자는 눈에 보인다.

**그때 22명 전체 통계**: 910행 중 정확히 30칸인 행이 288행뿐이었다(31.6%). 444행이 30칸 초과.
즉 대부분의 줄에서 칸이 어긋나 있었다. 한 번도 세어보지 않고 "판독 완료"라고 보고했다.

### 2-2. 판독 직후 반드시 기계적으로 검사한다

판독문을 저장한 **직후**, 사람 눈이 아니라 코드로 검사한다. 이 검사를 건너뛰지 않는다.

```python
# 모든 줄이 30칸인지 — 불확실 표시 ⟨ ⟩ 는 제외하고 센다
for i, t in enumerate(tx, 1):
    if not t.strip():
        continue
    n = len(t.replace('⟨', '').replace('⟩', ''))
    if n != 30:
        print('%d행: %d칸 — 다시 볼 것' % (i, n))
```

- 30칸이 아닌 줄은 **판독이 끝난 게 아니다.** 그 줄을 다시 본다.
- 마지막 줄을 제외하고 30칸이 아닌 줄이 남아 있으면 그 학생은 완료가 아니다.
- **칸 수가 안 맞는 줄은 글자가 맞아 보여도 불확실 표시를 한다.** 칸이 틀렸다는 건 무언가를 빠뜨렸거나 더했다는 뜻이다.

실제로는 `v30.py`로 검사한다(§1). 부호·괄호의 칸 규칙은 §4를 따른다.

### 2-3. 판독문에 주석을 섞지 않는다

`[여백]`, `[뒷장]`, `[순서바꿈]`, `[취소선]` 같은 표시를 **본문 줄 안에 넣으면 칸 계산이 깨진다.**
- 본문 줄에는 **학생이 쓴 글자와 빈칸만** 넣는다.
- 편집 기호(화살표 이동, 취소선, 삽입 표시)나 여백·뒷장 여부는 **학생 데이터의 `note` 필드에 따로 적는다.**
- 취소선으로 지운 칸은 빈칸으로 처리하고, 무엇을 지웠는지는 note에 적는다.

### 2-4. 글자 모양이 애매할 때

- **맥락으로 짐작해 채우지 않는다.** 작품명·인명·문법을 아는 지식으로 끌어다 맞춘 것이 전부 오류였다.
  (「목련 후기」를 「묏버들」로, '나는'을 '나ᄂᆞᆫ'으로 읽은 사례)
- 획 하나 차이 수준이면 맥락으로 읽되 **반드시 불확실 표시를 한다.**
- 전혀 안 보이면 `▯`로 칸을 채워 **칸 수는 지킨다.** 추측해서 글자를 넣지 않는다.
- 연필로 흐리게 지나간 획을 놓쳐 획이 적은 글자로 읽는 실수가 잦다: 간→란, 년→련, 제→체, 모→또, 두→주.

**추론해서 내용을 채우지 않는다 (2026-09-28 교사 지적으로 추가)**

판독은 "학생이 쓴 것"을 옮기는 일이지, "학생이 쓰려던 것"을 복원하는 일이 아니다.
뜻이 통하게 고친 판독문은 틀린 판독문이다. 오기·비문·어색한 말도 채점 자료다.

- **칸마다 그 순간 보고 있는 이미지에서만 글자를 정한다.** 요약·메모·이전 초안·기억해 둔 문장을 옮겨 적지 않는다.
  미리 적어 둔 대략의 문장은 칸 번호 확인용일 뿐, 판독문의 출처가 아니다.
- **보이는 모양 그대로 적는다.** 문맥상 기대되는 말과 달라도(예: '개시리', '끝임없이', '두 시 는 사 는') 보이는 대로 적는다.
  말이 안 되는 것 같으면 한 번 더 확대해 보고, 그래도 그렇게 보이면 그대로 둔다.
- **불확실 표시 안에도 기대하는 글자가 아니라 보이는 글자를 넣는다.** `⟨처⟩`처럼 뜻에 맞춘 글자를 넣고 괄호로 면피하지 않는다.
  모양조차 정할 수 없으면 `▯`.
- **작품 원문·인용 구절을 아는 지식으로 채우지 않는다.** 학생이 「가시리」·「이별 노래」 구절을 인용해도
  원문을 떠올려 맞추지 말고, 학생이 쓴 글자를 칸마다 읽는다. 틀리게 인용했으면 틀린 그대로 적는다.
- 글자 수가 모자라거나 남는다고 말을 지어 넣거나 빼서 15칸을 맞추지 않는다. 칸이 안 맞으면 다시 본다(§3-6).

### 2-5. 불확실 표시 방법 (서버 형식)

판독문 안에 `⟨글자⟩`로 감싼다.
- 교사 화면에서 그 줄이 빨갛게 뜨고, 오른쪽에 확인할 글자만 칩으로 따로 보인다.
- **입력칸에는 `⟨ ⟩`가 보이지 않는다.** 교사가 괄호를 지울 필요 없다. 맞으면 칩을 누르면 확정된다.
- 괄호는 **한 줄 안에서 열고 닫는다.** 줄을 넘어가면 표시가 깨진다.
  (줄 끝과 다음 줄 첫머리에 걸친 단어는 `…⟨신⟩` / `⟨화⟩와…` 처럼 각 줄에서 따로 닫는다)

**표시할 대상**
1. 글자 모양이 애매한 곳
2. **칸 수가 30이 아닌 줄 전체** (§2-2)
3. 학생이 원문을 잘못 인용했는데 오기인지 판독 실패인지 불분명한 곳

표시를 남발하지 않는다. 한 학생의 거의 모든 어절에 표시를 달면 교사가 쓸 수 없다.
그 정도로 안 읽히면 판독 방법을 바꾸거나, 그 학생은 교사에게 직접 보라고 알린다.

### 2-6. 원본으로만 판독한다

- **항상 원본 PDF에서 렌더링**한다. 내가 만든 축소 JPG·중간 산출물로 판단하지 않는다.
  (축소본을 읽어 해→태, 있→오로 잘못 읽은 사례)
- 블록 읽기는 150~170dpi, 글자 하나 확인은 700~1600dpi.
- 격자 좌표는 **파일에 적어 두고 그 파일을 다시 읽어 쓴다**(`tools/measured.json`). 기억에 의존하지 않는다.

### 2-7. 학생 번호·이름은 이름칸 원본에서 확인한다

- 학생이 반·번호를 잘못 쓴 경우가 있다(4반 3번이 "3반 4번"으로 씀).
- 판독 중 메모한 이름을 믿지 말고 **이름칸 이미지를 다시 보고** 확정한다.
  (2026-09-23에 4반 12번 이름을 판독 중 메모와 다르게 잘못 적은 적이 있다)
- PDF 쪽 번호 ↔ 반/번호/이름 대응표를 파일로 만들어 두고 그것을 기준으로 삼는다.
- 이름이 확실하지 않으면 뒤에 `(?)`를 붙이고, 알아볼 수 없는 글자는 `▯`로 둔다.

## 3. 판독 방법

칸 수 문제를 빼면 글자 판독 자체의 품질은 서브에이전트에 맡겼을 때보다 이 방식이 나았다.
교사 확인: "칸수 틀린 거 빼고는 판독 퀄리티 자체는 이전 에이전트들보다 좋았어."
그러니 **방식을 바꾸지 말고, 여기에 칸 검사만 더한다.**

### 3-1. 직접 읽는다. 서브에이전트에 맡기지 않는다.

- 2026-09-22에 서브에이전트 3개를 띄웠다가 전부 중단했다. 느린 데다 에이전트 로그에 스스로
  "unreliable transcriptions"라고 적어 놓았다. 내가 한 명 읽는 편이 더 빠르고 정확했다.
- 판독은 이미지를 반복해서 들여다보며 앞뒤 문맥과 대조하는 일이다. 컨텍스트를 나눠 주면 품질이 떨어진다.

### 3-2. 7행 블록으로 훑고, 애매한 곳만 확대한다.

- 한 장(35행)을 7행씩 5블록으로 렌더링해 읽는다. 150dpi면 충분하다.
- 블록 이미지는 한 번에 한 장씩 본다. 여러 장을 한꺼번에 보면 행이 섞인다.
- 애매한 글자만 칸 범위를 지정해 700~1600dpi로 확대한다.
- 글자 하나당 이미지를 만들면 토큰이 감당이 안 된다. 2026-09-22에 학생당 45장을 쓰다가
  교사에게 "토큰 소모가 많아도 너무 많다"는 지적을 받고 10장 안팎으로 줄였다.
- 학생당 블록 5~8장이면 충분하다.

### 3-3. 판독 순서 (학생 1명)

1. 이름칸(`{홀수쪽}h`)으로 반·번호·이름 확정 → 명단과 대조
   학생이 반·번호를 틀리게 쓴 경우가 있다 (4반 3번은 "3반 4번"으로 적었다).
   판독 중 메모한 이름을 믿지 말고 이름칸 이미지를 다시 본다
   (4반 12번 이름을 판독 중 메모대로 잘못 적은 적이 있다).
2. 1쪽을 **7행 블록 5개**로 읽는다 — `block <쪽> 1 7`, `8 14`, `15 21`, `22 28`, `29 35`
3. 애매한 글자만 `cell`로 확대 (700~1600dpi)
4. **2쪽 판단** — 아래 규칙
5. `s{반}_{번호:02d}.json` 저장
6. **`v30.py`로 검사** → 걸린 행을 다시 본다
7. 통과한 뒤에 다음 학생

한 명 끝낼 때마다 저장한다. 세션이 끊겨도 이어서 할 수 있다.

### 3-4. 2쪽(뒷장) 판단 — 교사 확정

- 학생마다 **2쪽씩** 스캔되어 있다. 빈 쪽도 다 스캔했다.
  교사가 눈으로 확인하려고 일부러 그렇게 한 것이니, 빈 쪽이 있다고 이상한 게 아니다.
- **2쪽 맨 위 2줄이 비어 있으면 그 쪽은 백지**로 본다. 그 아래는 읽지 않아도 된다.
- **다만 예외가 있다.** 2줄 이상 띄운 뒤 아래쪽에 이어 쓰거나,
  원고지 밖 여백에 쓴 학생이 있다 (3반 4번·12번, 4반 2번).
  그래서 **2줄 규칙에 걸려도 쪽 전체를 한 번은 훑는다.**
  `block <2쪽> 8 14`, `15 21` 정도만 더 보면 충분하다.
- 1쪽이 백지인 경우는 거의 없다.
- 번호·이름 머리가 없는 쪽은 **앞 학생의 뒷장**이다.
- 원고지 밖 여백에 쓴 줄도 답안에 포함해 판독하고 분량에도 넣는다.
  그 줄은 칸 격자가 없으므로 30칸 검사에서 예외로 두고, `note`에 적는다.

### 3-5. 진행 상황은 학생 단위로 저장한다

- 학생 한 명 끝날 때마다 `s{반}_{번호:02d}.json`으로 저장한다.
- 세션이 끊기거나 컨텍스트가 넘쳐도 거기서부터 이어서 할 수 있다.
- 저장 형식: `{"n":번호, "name":"이름", "work":"선택작품", "tx":[행...], "chars":글자수, "note":"편집기호·특이사항"}`

### 3-6. 칸이 안 맞으면 반쪽 확대 + 칸 번호로 적는다 (2026-09-28 추가)

- 7행 블록으로 문장을 읽고 옮겨 적으면 띄어쓰기·부호 칸을 놓쳐 29칸·31칸 줄이 계속 나온다.
  한 학생에서 초과·미달 줄이 여럿 나오면 문장으로 적는 것을 멈추고 방법을 바꾼다.
- `halves.py <쪽> <행...>` 은 한 행을 1~15칸 / 16~30칸 두 줄로 나눠 크게 보여 준다
  (`GAMMA=2.5` 를 주면 흐린 연필을 어둡게 보정한다. 원본 PDF에서 바로 렌더링한다).
- 그 이미지를 보며 `칸번호:글자` 로 적고(`1:개 2:여 3:울 5:과 ...`, 빈칸은 적지 않음)
  `cellrow.py` 로 행을 만든다. **칸 번호로 적으면 칸 수가 틀릴 수가 없다.**
- 이 방식으로 적은 7반 16~21번은 첫 작성에서 칸 수가 맞았다(반쪽 줄을 짝지을 때 한 줄 밀린 1건 제외).

## 4. 판독문 표기와 JSON 형식

```json
{
 "n": 3,
 "name": "홍길동",
 "work": "목련 후기",
 "pages": [5, 6],
 "tx": ["1행", "2행", "..."],
 "chars": 0,
 "note": "편집기호·특이사항. 본문 줄에는 주석을 넣지 않는다"
}
```

- `pages`는 **PDF 쪽 번호** (1쪽, 2쪽)
- `tx`는 원고지 행 순서대로. 1쪽 35행 다음에 2쪽이 이어진다
- 띄어쓰기는 **원본 그대로**. 고치지 않는다 (채점 항목이다)
- 불확실한 곳은 `⟨글자⟩`. **한 줄 안에서 열고 닫는다**
  (줄을 넘어가는 단어는 `…⟨신⟩` / `⟨화⟩와…` 처럼 각 줄에서 따로 닫는다)
- `[여백]`, `[순서바꿈]`, `[취소선]` 같은 표시는 **`note`에만** 적는다.
  본문 줄에 넣으면 칸 계산이 깨진다

### 부호·괄호·한 칸 두 글자 표기 (2026-09-23~28 정함)

칸 검사(`v30.py`)가 원고지 칸과 같게 세도록 부호를 이렇게 적는다.

| 원고지 | 판독문 표기 | 칸 수 |
|---|---|---|
| 괄호·따옴표가 **따로 한 칸** | `( ) ' "` | 1칸 |
| 괄호·따옴표가 **글자와 같은 칸** | 전각 괄호 `（ ）`, 둥근 따옴표 `‘ ’ “ ”`, 낫표 `「 」` | 붙은 글자에 포함 |
| 마침표·쉼표가 앞 글자와 같은 칸 | `. ,` | 앞 글자에 포함 |
| 마침표·쉼표가 **앞 빈칸 없이 따로 한 칸** | 전각 `． ，` | 1칸 |
| 한 칸에 두 글자(`45`, `13`, `있다`) | 두 글자 사이에 U+200D(보이지 않는 결합 문자) | 1칸 |
| 전체를 X·취소선으로 지운 줄 | 빈 줄(`""`) — 행 번호를 지키기 위해 빼지 않는다 | 0 |

- 종이를 뒤집어 거꾸로 쓴 줄은 180도 돌려 읽고, 스캔상의 위치를 note 에 적는다(7반 1번).
- 행과 행 사이 작은 글씨 삽입·화살표 이동은 본문에 넣지 않고 note 에 적는다(§2-3).

## 5. 서버에 올리기

판독 결과는 Cloudflare Worker(`suhaeng1`)의 `src/data.js`에 넣어 배포한다.

```sh
# 1) 서버의 현재 DATA 를 받는다. Cloudflare API(content/v2)를 wrangler 토큰으로 호출하거나
#    브라우저 페이지에서 JSON.stringify(DATA) → Blob → 다운로드 (아래 "규칙")
# 2) 받은 DATA 에 '추가'만 한다: 새 반은 추가, 있는 반은 빈 학생 칸만 채운다.
#    받은 DATA 와 새 DATA 를 비교해 의도한 곳 말고는 바뀐 곳이 없는지 확인
# 3) bash deploy.sh
```

**로컬 `data.js`가 최신이라고 가정하지 말 것.**
2026-09-23에 그렇게 해서 다른 반 판독문과 교사가 수정한 화면 코드를 전부 날렸다.
복구는 `npx wrangler rollback <version-id>`로 했다.
(`wrangler deployments list`의 시각은 **UTC**다. 한국시간은 +9시간)

`deploy.sh`는 `tools/guard.py`를 거친다. 이전 배포보다 **반이 사라지거나
학생 수가 줄면 배포를 막는다.** 의도한 삭제라면 `tools/deployed_classes.json`을
지우고 다시 실행한다.

### 규칙 (2026-09-23 배포 사고 뒤 정함)

2026-09-23, `wrangler deploy` 한 번으로 1·2·3·7·8반 판독문과 교사가 리뉴얼한 화면 코드를 전부 날렸다.
Cloudflare 버전 롤백(`wrangler rollback <version-id>`)으로 복구했다.

**원인**
- 로컬 `data.js`가 서버 최신본이라고 **확인 없이 가정**했다.
- 배포 전 검증이 `반 ['1','4']`를 출력했는데 "1반 연습 + 4반 신규"로 멋대로 해석하고 넘어갔다.

**규칙**
- 배포 전에 **서버의 현재 data.js를 받아** 반 목록을 비교한다. 로컬이 최신이라고 가정하지 않는다.
- `tools/guard.py`가 이전 배포의 반 목록과 비교해 **반이 사라지거나 학생 수가 줄면 배포를 막는다.**
  의도한 삭제라면 `tools/deployed_classes.json`을 지우고 다시 실행한다.
- `deploy.sh`를 통해서만 배포한다. `npx wrangler deploy`를 직접 치지 않는다.
- 서버 페이지를 받는 법 (2026-09-23 확인): **Cloudflare API로 현재 배포본을 받는다.**
  사이트 주소는 Access 때문에 curl이 안 되지만, API는 wrangler 로그인 토큰으로 된다.
  `curl -H "Authorization: Bearer <wrangler oauth_token>" https://api.cloudflare.com/client/v4/accounts/<계정ID>/workers/scripts/suhaeng1/content/v2`
  → 응답(멀티파트)에서 `var DATA = {...};` 를 뽑는다(`_prev/ext.js`). 토큰은 `npx wrangler whoami` 로 갱신된다.
  브라우저 방법(`fetch('/')` → Blob)도 여전히 쓸 수 있다.
- **올릴 때는 서버 DATA 에 "추가"만 한다.** 새 반은 새로 넣고, 이미 있는 반은 비어 있는 학생 칸만 채운다.
  배포 전에 받은 서버 DATA 와 새 DATA 를 비교해 **의도한 곳 말고는 바뀐 곳이 없음**을 확인한다.
- 교사 수정(판독문·이름·점수·피드백)은 data.js 가 아니라 **D1 `edits` 테이블**에 따로 쌓인다. 배포로 지워지지 않는다.
  화면이 행 번호 기준으로 덮어 보여 주므로, **수정 기록이 있는 학생의 tx 는 행 번호를 바꾸지 않는다.**
  백업: `npx wrangler d1 export suhaeng-edits --remote --output d1_dump.sql`
- 복구 수단은 롤백뿐이다: `npx wrangler deployments list`로 시각 확인
  (**UTC로 표시된다. 한국시간은 +9시간**), `npx wrangler rollback <version-id>`.

### 불확실 표시가 화면에서 보이는 방식

판독문의 `⟨글자⟩`는 교사 화면에서
- 그 줄이 빨갛게 표시되고
- 오른쪽에 확인할 글자만 칩으로 따로 나오고
- **입력칸에는 `⟨ ⟩`가 보이지 않는다** (교사가 괄호를 지울 필요 없음)
- 맞으면 칩을 눌러 확정, 틀리면 입력칸에서 글자만 고치면 된다

### 화면의 분량 표시

2026-09-28부터 교사 화면은 **교사가 고친 판독문으로 분량을 실시간 계산해 보여 준다**(`page.html` 의 `charsOf`).
판독문을 고치면 목록·카드 머리말·930자 감점 안내의 분량이 바로 바뀐다. data.js 의 `chars` 값은 화면에 쓰이지 않는다.
분량을 어떻게 세는지(채점 기준)는 채점 지침 §0 "답안지와 분량"을 따른다.
